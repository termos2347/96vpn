# 96VPN Bot

Telegram-бот для продажи VPN-подписок с интеграцией 3x‑UI, ЮKassa и Telegram Stars.

## Возможности
- VPN-подписки через пул серверов 3x‑UI.
- Оплата через ЮKassa (RUB), Telegram Stars, USDT (через ссылку).
- Автоматическое создание/отзыв ключей.
- Напоминания об истечении, фоновые задачи.
- Административный бот для управления пользователями, серверами, рассылками.

## Технологии
- aiogram 3.x
- aiohttp (внутреннее API)
- PostgreSQL, SQLAlchemy, Alembic
- Yookassa SDK, cryptography, tenacity

## Установка
1. Клонируйте репозиторий.
2. Создайте виртуальное окружение и установите зависимости (`pip install -r requirements.txt`).
3. Скопируйте `.env.example` в `.env` и заполните обязательные переменные.
4. Примените миграции: `alembic upgrade head`.
5. Запустите: `python run_all.py`.
```
git clone https://github.com/your-repo/96vpn-bot.git
cd 96vpn-bot
python3 -m venv .venv
source .venv/bin/activate          # для Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Архитектурные особености
- Бот работает **только в одном экземпляре** (однопроцессный).
- **Rate limiting** и **кэш** хранятся в оперативной памяти и сбрасываются при перезапуске бота.
- Для горизонтального масштабирования (несколько воркеров) потребуется внешнее хранилище (Redis, Memcached) и централизованное управление сессиями.
- В текущей версии Redis **не используется** и не поддерживается.

## Архитектурные ограничения и масштабирование

На текущем этапе разработки бот **предназначен для работы в одном экземпляре на одном сервере**. Это сознательное архитектурное решение, позволяющее упростить развертывание и избежать сложностей с распределёнными состояниями.

### Что это означает?

- **Хранение данных в оперативной памяти**  
  Все механизмы, использующие память (rate limiting, кэш статусов подписок, блокировки пользователей), хранятся в глобальных переменных Python и **сбрасываются при перезапуске бота**. Это приемлемо для малых и средних нагрузок, но не гарантирует сохранность состояния при авариях.

- **Отсутствие Redis, Memcached и других внешних хранилищ**  
  В текущей версии не используется Redis или аналоги для распределённого кэширования или синхронизации. Это значит, что **запуск нескольких экземпляров бота в параллель невозможен** без серьёзной переработки (например, внедрения централизованного хранилища для rate limiting, блокировок и кэша).

- **Однопроцессная модель**  
  Все компоненты (основной бот, админ-бот, внутреннее API, фоновые задачи) работают в одном процессе. Это упрощает управление, но ограничивает производительность одним ядром CPU и не позволяет использовать все преимущества многоядерных систем. Для увеличения пропускной способности потребуется перейти на многопроцессную архитектуру (например, с использованием `gunicorn` или `uvicorn` для aiohttp) и синхронизировать состояния через внешние сервисы.

### Для кого подходит текущая версия?

- Для старта проекта с нагрузкой до нескольких тысяч пользователей.
- Для тестирования и разработки.
- Для случаев, когда не требуется высокий уровень отказоустойчивости и масштабирования.

### Планы по улучшению

В будущих версиях планируется поддержка:
- Redis для кэша, rate limiting и распределённых блокировок.
- Нескольких экземпляров бота за балансировщиком (с использованием вебхуков и общего хранилища).
- Управления сессиями через внешнюю базу данных.

Однако на данный момент **эти функции отсутствуют**, и мы рекомендуем придерживаться однопроцессной схемы, описанной в инструкции по запуску.
